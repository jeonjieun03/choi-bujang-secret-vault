# 마지막 총공세 작업 기록 (학생 작성)

작전: 화면 틀 **관제 대시보드형**(맨 위 상태 카드 네 개, 아래 추이와 기록) · 포장 형태 **포장 없이 프로젝트 폴더에서 실행**(`npm run package-app` 등 포장 명령은 실행하지 않음).

### 학생 화면 규칙

- 「내 PC 실측 조회」를 누를 때만 한 번 읽음(자동 조회·타이머 없음). 키보드 Enter로도 동작.
- 값마다 단위와 잰 시각(`measuredAt`), 출처(`local-pc`)를 붙임. GB는 제공 카드와 같은 1024³ 기준.
- 읽지 못한 항목은 0이나 예시 값 대신 「확인 불가」와 이유(권한 없음·시간 초과·지원 안 함·형식 확인 불가 등). 조회 자체가 실패하면 네 칸 모두 확인 불가, 지난 값은 현재 상태로 쓰지 않음.
- 측정 후 60초가 지나면 「오래됨」.
- 주의 기준: CPU 85% 이상, 메모리 90% 이상, 디스크 남은 공간 10% 미만, 꺼진 방화벽 프로필. 「주의」는 확인이 필요하다는 뜻이며 악성코드·침해 판정이 아님. 방화벽이 켜져 있다는 것도 안전 판정이 아님.
- 이 칸에는 예시 값을 표시하지 않음.

### CPU 값이 작업 관리자와 다른 이유 (원문 확인)

- 작업 관리자는 약 1초 단위의 평소 이용률을 보여 줍니다.
- 앱은 「내 PC 실측 조회」를 누른 순간의 0.2초 표본입니다(`src/pc-status.mjs`의 `pause(200)`).
- 같은 함수가 CPU 표본을 재는 동안 방화벽·Windows 기록을 읽기 위해 `powershell.exe`를 함께 실행합니다(`Promise.all([cpu, drive, windows])`). 그 실행이 표본 구간의 CPU를 올리므로 앱 값이 더 높게 나올 수 있습니다.
- 제공 코드는 고치지 않고, 학생 CPU 카드에 이 한계를 적었습니다. 측정 시점과 집계 범위가 다르므로 앱 CPU 값을 작업 관리자 값 대신 쓰지 않습니다.

### 같은 결과를 다시 만드는 방법

```powershell
cd $HOME\Documents\keshev
git pull
cd on-client
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

1. 브라우저에서 `http://127.0.0.1:5189/` 를 열고(이미 열려 있으면 `Ctrl+F5`) 「보호 현황」으로 갑니다.
2. 제공 카드 「내 PC 상태」에서 「내 PC 확인」을 누르고 값을 봅니다.
3. 아래 「학생 상태·알림 표시」 칸의 「내 PC 관제 대시보드」에서 「내 PC 실측 조회」를 누릅니다. 제공 카드와 같은 단위·비슷한 시각의 값인지 비교합니다(CPU는 0.2초 표본이라 조회마다 달라질 수 있음).
4. 한 번 더 눌러 ▲▼ 변화와 「지난 실측」 시각이 나오는지 봅니다.
5. 끌 때는 PowerShell 창에서 `Ctrl+C`.

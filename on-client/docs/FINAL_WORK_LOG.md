### 학생 화면 규칙

- 「내 PC 실측 조회」를 누를 때만 한 번 읽음(자동 조회·타이머 없음). 키보드 Enter로도 동작.
- 값마다 단위와 잰 시각(`measuredAt`), 출처(`local-pc`)를 붙임. GB는 제공 카드와 같은 1024³ 기준.
- 읽지 못한 항목은 0이나 예시 값 대신 「확인 불가」와 이유(권한 없음·시간 초과·지원 안 함·형식 확인 불가 등). 조회 자체가 실패하면 네 칸 모두 확인 불가, 지난 값은 현재 상태로 쓰지 않음.
- 측정 후 60초가 지나면 「오래됨」.
- 주의 기준: CPU 85% 이상, 메모리 90% 이상, 디스크 남은 공간 10% 미만, 꺼진 방화벽 프로필. 「주의」는 확인이 필요하다는 뜻이며 악성코드·침해 판정이 아님. 방화벽이 켜져 있다는 것도 안전 판정이 아님.
- 이 칸에는 예시 값을 표시하지 않음.

### CPU 값이 작업 관리자와 다른 이유 (원문 확인)

- 작업 관리자는 약 1초 단위의 평소 이용률을 보여 줍니다.
- 앱은 「내 PC 실측 조회」를 누른 순간의 0.2초 표본입니다(`src/pc-status.mjs`의 `pause(200)`).
- 같은 함수가 CPU 표본을 재는 동안 방화벽·Windows 기록을 읽기 위해 `powershell.exe`를 함께 실행합니다(`Promise.all([cpu, drive, windows])`). 그 실행이 표본 구간의 CPU를 올리므로 앱 값이 더 높게 나올 수 있습니다.
- 제공 코드는 고치지 않고, 학생 CPU 카드에 이 한계를 적었습니다. 측정 시점과 집계 범위가 다르므로 앱 CPU 값을 작업 관리자 값 대신 쓰지 않습니다.

### 화면 규칙

- 버튼: 처음 「내 PC 조회」, 그 뒤 「다시 조회」. 누르면 「읽는 중…」과 「잠시 기다려 주세요(N번째 조회)」, `aria-busy=true`. 읽는 동안 다시 눌러도 요청하지 않음.
- 키보드: Tab으로 버튼에 가서 Enter. 화면이 다시 그려져도 초점이 버튼에 남아 Enter를 이어서 누를 수 있음(다른 곳으로 옮긴 초점은 건드리지 않음).
- 전체 실패: 빨간 안내 칸(`role=alert`)에 원인·안 된 항목 6개·다음에 할 일(원인별: NETWORK_ERROR → PowerShell 창 확인·다시 켜기·다시 조회, TIMEOUT → 잠시 뒤 다시 조회, NOT_ALLOWED → 시작 틀 0.2.21 확인). 지난 성공 값은 현재 상태로 쓰지 않고 예시 값으로 채우지 않음.
- 일부 실패: 읽지 못한 항목만 이유와 다음에 할 일(권한 없음 → 담당자 확인, 지원 안 함 → Windows 전용 항목, 시간 초과 → 다시 조회).
- ② 상태 추이: 성공한 조회마다 잰 시각·CPU 사용률·메모리 사용률(막대 `<meter>`와 숫자)·디스크 남은 공간·방화벽 켜짐 수, 최근 10개.
- ③ 점검 기록: 성공(주의 N · 확인 불가 N)과 실패(요청 시각 · 코드)를 최신 순, 최근 20개.
- 추이·기록은 화면 메모리에만 있고 저장하지 않음(새로 고치면 지워짐).

### 같은 결과를 다시 만드는 방법

1. 앱 폴더에서 `git pull` 뒤 기본 실행으로 앱을 켭니다.
2. 브라우저에서 `Ctrl+F5`. 「보호 현황」 위쪽에 학생 칸이 먼저 보이는지 봅니다.
3. Tab으로 「내 PC 조회」 버튼에 가서 Enter → 「다시 조회」로 바뀌면 Enter를 두세 번 더 누릅니다. ② 추이와 ③ 기록이 한 줄씩 늘어나는지 봅니다.
4. PowerShell 창에서 `Ctrl+C`로 앱을 끈 뒤 브라우저에서 「다시 조회」 → 빨간 오류 안내와 기록의 「조회 실패」를 봅니다.
5. 앱을 다시 켜고 「다시 조회」 → 오류 안내가 사라지는지 봅니다.

# 케셰브 최종 커밋 새 환경 재현 기록 (22단계, 학생 작성)

이 문서는 **학생 진술(재현 기록)**입니다. 서버나 판정 AI가 새 환경에서 실행했다는 뜻이 아니며, AI 원문 검토 통과를 실행 성공의 증명으로 쓰지 않습니다. 버전·지원 범위는 [RELEASE.md](RELEASE.md), 실행 방법과 구성도는 [STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md)에 있습니다.

## 표시 구분

| 표시 | 뜻 |
|---|---|
| **실제 실행** | 새 폴더에 받은 코드로 서버를 켜고 브라우저(Chromium)에서 화면을 직접 관찰한 결과. 예제 모드(`--demo`)인지 기본 실행(연결 없음)인지 함께 적음 |
| **모의 입력** | 새 폴더의 `student/extension.mjs`를 브라우저에서 불러와 학생 함수에 모의 데이터를 넣어 본 결과. 실제 시스템 연결 결과가 아님 |
| **원문 확인** | 실행하지 않고 코드·문서를 읽어 확인한 것 |
| **미확인** | 확인하지 못한 것과 그 원인 |

## 3. 수행 절차 (실제로 실행한 명령)

```text
# 1) 새 빈 폴더에서 해당 커밋 받기
git clone --branch keshev-submit https://github.com/jeonjieun03/choi-bujang-secret-vault.git keshev
cd keshev
git rev-parse HEAD                      # → d25713cdccaa8405e2666b6fc721cd41699e7f08

# 2) 런타임 확인과 문법 확인 (앱 폴더)
cd on-client
node --version                          # → v22.22.0
npm run check                           # → node --check student/extension.mjs, 종료 코드 0

# 3) 설치: 외부 npm 의존성이 없어 npm install 단계 없음 (package.json에 dependencies 없음)

# 4) 기본 실행 → 브라우저 확인 → 종료 → 다시 실행
node src/server.mjs                     # npm start 와 같은 명령
#   (브라우저) http://127.0.0.1:5189/
#   종료: Ctrl+C 와 같은 SIGINT 신호
node src/server.mjs                     # 다시 실행, 다시 SIGINT 로 종료

# 5) 예제 실행 → 메뉴별 확인 → 다시 불러오기 → 종료
node src/server.mjs --demo              # npm run demo 와 같은 명령
```

Windows PowerShell 실행 도구(`.\tools\start-alekov.ps1`)는 이 환경에서 실행하지 못했습니다(미확인, 4장).

### 백업

1. 단계마다 프로젝트 폴더에서 커밋하고 GitHub(`origin`)에 올립니다. 원격 저장소가 1차 백업입니다.
2. 브랜치는 둘을 유지합니다. `main`(1~12단계 방어전 + 케셰브 전체 작업), `keshev-submit`(판정용 `on-client`만, 판정 AI 읽기 크기 제한 때문에 만듦). 두 브랜치의 `on-client` 내용은 같게 유지합니다.
3. 비밀 설정(`.env`, 열쇠, 인증서, 담당자 설정 파일)은 백업 대상에 넣지 않습니다. 잃어버리면 담당자에게 다시 발급받습니다.

1. 새 빈 폴더에서 `git clone --branch keshev-submit https://github.com/jeonjieun03/choi-bujang-secret-vault.git`
2. 특정 버전이 필요하면 `git checkout <40자리 커밋>` (기존 커밋을 지우거나 되돌리지 않음, `git reset --hard` 사용하지 않음)
3. `on-client`에서 `npm run check`로 학생 파일 문법을 확인한 뒤 STUDENT_RUNBOOK 4장대로 실행합니다.

### 제한

- 화면에서 본 결과(판정·설명·조치 상태)는 앱이 저장하지 않으므로 복원 대상이 아닙니다. 다시 불러와야 합니다.
- 원본 기록·조치 영수증은 회사 시스템과 조치 DB 쪽에 있으며, 학생 저장소로는 복원할 수 없습니다.
- 이번 복원 절차는 위 3장 재현에서 1·3단계를 실제로 수행했습니다. 2단계(`git checkout <커밋>`)는 이번 재현에서 따로 수행하지 않았습니다.
